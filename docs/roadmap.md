# AI Concept Visualizer — 課程地圖與開發藍圖 (Roadmap)

> 專案定位：一條「從完全不懂到理解 AI 是什麼」的分級互動學習路徑。
> 核心故事線：懂教學現場的 AI 應用開發者 — 每一頁都要回答「為誰做、解決什麼誤解、為什麼這樣設計」。

---

## 一、三層架構（學習者的閱讀順序）

### 初級：AI 到底是什麼（不碰數學）
目標讀者：完全沒接觸過 AI 的高中生（GET 社團、補習班學生皆適用）
要產生的 aha：「寫規則會失敗的事，用『學』的居然可以」

規劃頁面：
1. **從規則到學習（派典時間軸 + 兩個動手實驗）** — ✅ 初版完成 9/17，詳見第十節
2. **訓練 vs 推論：模型「上課」和「考試」是兩件事** — ✅ 完成 10/2，詳見第十三節
3. **AI 為什麼會錯：資料偏差與幻覺** — ✅ 完成 10/7，詳見第十四節 —— 初級三頁全部完成

### 中級：機器是怎麼「學」的（本學期主力，10 月中完成）
目標讀者：讀完初級、想知道「學習」背後機制的人
要產生的 aha：「機器學習 = 一個會自我修正的函數」

頁面（閱讀順序）：
1. `neural_network.html` — 模型長什麼樣子、資料怎麼流過去（forward pass）
2. `gradient_descent.html` — 機器怎麼修正自己：往誤差變小的方向走
3. `backpropagation.html` — 梯度實際上怎麼算出來

### 高級：現代 AI 的引擎室（明年，與 iPAS 中級準備銜接）
規劃主題（backlog，暫不展開）：
- Transformer / attention 機制
- Diffusion model 去噪過程（雜訊中浮現圖像、滑桿控制去噪步數）
- 其他機器學習方法的視覺化（決策樹、k-means…）
- 往 iPAS AI應用規劃師中級考綱靠的應用規劃內容

## 五、gradient_descent.html 教學設計決定（9/10 定案）

| 決定 | 選擇 | 理由 |
|---|---|---|
| 曲線地形 | 單谷（預設）＋雙谷可切換 | 雙谷多教一個「局部最小值 local minimum」，且讓「起點決定命運」變成可操作的體驗 |
| 術語深淺 | 介面用「誤差」，首次出現時括號附（損失函數 loss function） | 高中生沒學過損失函數；先給體感再給名詞 |
| 互動節奏 | 預設單步，可切自動播放 | 預測 → 驗證的節奏教學效果最好；自動播放當輔助 |

### 頁面設計要點
- **球是「跳」不是「滾」**：刻意用虛線弧＋離散跳躍動畫，避免學生以為梯度下降是連續滑動（常見誤解）
- **坡度箭頭**：長度隨梯度大小改變，讓「坡越陡跳越遠」變成看得見的因果
- **誤差記錄 sparkline**：對應真實訓練的 loss curve，是往中級後兩頁銜接的伏筆
- **三張實驗卡**：龜速（lr<0.1）、暴衝／發散（lr>2.0）、命運（雙谷換起點）— 每張都是可複現的操作指令，不是說明文字
- **收尾**：一個參數 → 上兆個參數 → learning rate 是超參數 → 下一頁反向傳播

### 設計系統（全站共用）
- 色：墨綠 `#22685A`（主要動作）、暖橘 `#E07B2E`（強調／警示）、紙感灰綠底 `#F5F7F4`
- 字：Noto Serif TC（標題）／ Noto Sans TC（內文）／ IBM Plex Mono（數值）
- 深淺色主題皆已處理；中文全形標點
- 術語彈出視窗（`.term` + `#pop` + `TERMS` 字典）與生活化比喻（「打個比方」標籤）已成為全站固定機制

## 六、neural_network.html 教學設計決定（9/10 定案，9/13 修正，9/27 情境改版）

> 9/27：情境從「手搖飲評分」改為「抽卡遊戲鑑定」，數字、權重、網路結構完全不變，只換文字／標籤／比喻。細節與理由見第十二節。

| 決定 | 選擇 | 理由 |
|---|---|---|
| 任務情境 | 手搖飲好不好喝（甜度／冰塊／珍珠 → 好喝程度） | 學生有強烈直覺；「好喝」是主觀的，順勢埋下「模型學的是誰的偏好」伏筆 |
| 互動主軸 | 輸入可調 ＋ 權重可調（點線編輯） | 只調輸入學生碰不到模型本身；權重可調才建立得起「權重就是模型的全部」 |
| 是否含訓練 | 含「自動訓練」按鈕 | 定位為**製造問題**而非提前解答：手動調很累 → 自動訓練 → 「它怎麼知道往哪調？」→ 導向梯度下降 |

### 9/13 修正：前向傳遞動畫
- 問題：原本兩段動畫（輸入→隱藏、隱藏→輸出）自動連播，總長約 1 秒，文字說明來不及看就被下一段蓋掉
- 修正：改成**分兩段、各自要點一下才播下一段**。按鈕文字也從「看它流過去」改成「送去試喝檢測」，扣回試喝團比喻。點第一次跑第一段並停在文字說明上，點第二次才跑第二段
- 換飲料／打亂權重會把按鈕重置回初始狀態，避免卡在中間段

### 頁面設計要點
- **架構**：3 → 2 → 1，共 11 個權重與偏誤；tanh（隱藏層）+ sigmoid（輸出）
- **線的編碼**：粗細 = |權重|，墨綠 = 正（加分）、磚紅 = 負（扣分）、接近 0 轉灰
- **訓練資料 = 「阿哲喝過的 5 杯 + 他的評分」**：讓「模型學的是某個人的口味」變成可驗證的體驗
- **誤差 sparkline**：與 gradient_descent 的 loss curve 視覺一致，三頁共用同一個視覺語言
- **版面穩定**：權重編輯面板與誤差圖表都預留固定高度，實測位移 0

### 三頁的敘事接力
```
neural_network  →「權重就是模型的全部」，但它怎麼知道往哪調？
gradient_descent →「看坡度，往誤差變小的方向跳一步」，但坡度怎麼算？
backpropagation  →（下一頁）梯度怎麼從輸出一路算回每一條線
```

## 七、backpropagation.html 教學設計決定（9/11 定案，9/27 情境改版）

> 9/27：情境與第六節同步改為「抽卡遊戲鑑定」，理由與對照表見第十二節。

| 決定 | 選擇 | 理由 |
|---|---|---|
| 主軸比喻 | 究責鏈（接第一頁的試喝團） | 「責任按被信任的程度往回分配」正好就是連鎖律，不是打比方打得剛好而已 |
| 網路 | 與第一頁完全相同的 3→2→1、同一份阿哲資料 | 學生在**已經認識的網路**上看新機制，認知負荷全部留給反向傳播本身 |
| 數字呈現 | 責任比例（%）為主，點單一條線才展開真正的算式 | 想深入的挖得到，不想的不被小數點淹沒 |

### 核心設計：同一組線，兩種編碼
- **前向階段**：粗細 = |權重|，綠=正、紅=負
- **反向階段**：粗細 = 責任大小，統一磚紅色
- 圖例會隨階段改寫，並明確警告「這個階段線的粗細換了意思」— 這個切換本身就是教學點

### 其他要點
- **四階段單步**：送一杯 → 算誤差 → 往回追責 → 照責任修正；STEP 3 的圓點是**由右往左**流，且顏色與前向不同，用來防「資料倒著流回去」這個誤解
- **連鎖律用白話展開**：點一條輸入層的線會看到「最後錯了多少 × 主管對評審A的信任 × 評審A的靈敏度 × 珍珠的量 = 這條線的責任」
- **靈敏度 (1−h²) 講成「這位評審還推得動嗎」**：意見已經很極端的評審責任反而小 — 順勢埋下梯度消失的種子
- 點擊感應區從 18px 縮到 11px，避免相鄰的線互搶點擊

### 三頁完成
```
neural_network   權重就是模型的全部，但它怎麼知道往哪調？
gradient_descent 看坡度往誤差變小的方向跳，但坡度怎麼算？
backpropagation  從輸出往回追責任，一層一層乘出來
```

## 八、index.html（9/11 完成）

定位不是「三頁的目錄」，而是**一張學習地圖**：左側一條登山軌串起初／中／高三層，中級是實心點且卡片可點，初級與高級是空心點與虛線「規劃中」卡。展示規劃能力本身就是作品集的加分項。

底部另設「這些頁面怎麼設計的」四條原則，是給看作品集的人看的：
1. **先體驗，再命名** — 術語永遠出現在學生已經做過那件事之後
2. **每個比喻都要經得起追問** — 比喻是為了精確，不是為了親切
3. **針對誤解，不是針對知識點** — 每頁先設定一個要拆掉的錯誤心智模型
4. **可操作才算數** — 挑戰卡是可複現的操作指令，不是說明文字

## 十、rule_to_learning.html 教學設計決定與完成（9/17 定案）

解決了第三節留下的「貓狗實驗素材與反例設計」待討論項目。

| 決定 | 選擇 | 理由 |
|---|---|---|
| 素材 | 不用真實照片，改用參數化 inline SVG「生物卡」 | 維持單檔可攜性；且能精準控制每張卡的特徵組合，反例才設計得出來 |
| 特徵集 | 耳朵（尖／圓）、鬍鬚（有／無）、瞳孔（豎／圓）、尾巴（蓬鬆／短）、體型（小／中） | 五個二元特徵，學生一眼就看得出差異，足夠組出有戲劇效果的反例 |
| 資料集 | 手工設計 14 隻（7 貓 7 狗） | 任何單一特徵當規則，正確率都卡在 64%–71%，逼出「規則永遠有例外」這個體驗，而不是隨機生成碰運氣 |
| 實驗二的訓練／測試切分 | 學生點卡片「加進訓練資料」時直接顯示正確答案（不是讓學生用外觀猜貓狗） | 對應真實 ML 的訓練資料定義：範例是連同正確答案一起給的，不是機器自己猜的 |
| 分類演算法 | 最近鄰（Hamming distance），k = min(3, 已標記數量），多數決 | 免真的訓練模型，且能在教學現場的裝置上瞬間跑完 |

### 實驗一・你來當規則工程師
- 下拉選單挑一個特徵當判斷依據（例：「有鬍鬚 → 算貓」），即時套用到全部 14 隻，紅框標出猜錯的
- 可加一條「而且」條件做 AND 規則，但仍然卡在 70% 左右 — 刻意讓學生發現「加規則不是解法」

### 實驗二・改用餵範例
- 同一副牌重新出牌，學生點卡片把它加進訓練資料（正確答案立即顯示），至少需選 6 隻且貓狗都要有
- 按下「讓機器分類剩下的」，用未標記卡片與訓練卡片的特徵距離做最近鄰分類
- 結果會與實驗一的規則正確率並排顯示，直接比較「同一份資料，兩種方法」

### 三個挑戰卡（呼應兩個實驗）
1. 換一個特徵當規則，看正確率會不會一直卡在七成
2. 只挑 6 隻當訓練資料，看範例學習的正確率掉多少
3. 找出規則和範例學習都判斷錯的那一隻，看牠的特徵組合特別在哪

### 收尾
呼應中級三頁：特徵從 5 個變成幾百萬個、資料從 14 筆變成幾十億筆，就是深度學習「規則多到人看不懂」的來源；同時誠實交代範例學習不是萬靈丹，為下一頁（初級 2「AI 為什麼會錯」）埋伏筆。

## 十二、情境改版：手搖飲 → 抽卡遊戲（9/27 定案）

### 起因
使用者回饋 `neural_network.html` 的自動訓練動畫「跑太快了，想要視覺化、又要有動態脈絡感」，同時提出手搖飲情境可能不是最有共鳴的例子，列了生圖、寫作、抽卡遊戲、理科問題幾個候選。討論後確認兩件事都要處理：**訓練節奏**與**情境本身**。

### 決定

| 決定 | 選擇 | 理由 |
|---|---|---|
| 新情境 | 抽卡遊戲鑑定 | 比手搖飲更貼近這個年齡層的直覺共鳴；「稀有度／數值／立繪」三個維度剛好對應真實特徵工程裡「類別、數值、視覺」三種不同性質的特徵，比甜度／冰塊／珍珠更有延伸教學價值 |
| 改動範圍 | `neural_network.html` 與 `backpropagation.html` 兩頁同步改 | 兩頁刻意共用同一份網路與資料（見第七節），情境換了一頁不換另一頁會互相矛盾 |
| 改動邊界 | **只換文字、標籤、比喻；數字、權重初始化邏輯、`DATA` 訓練資料、網路結構（3→2→1）完全不動** | 這是使用者在確認時明確畫的線 —— 情境是包裝，底層數學才是教學重點，換皮不能連帶改變任何學生看到的數字 |

### 對照表

| 舊（手搖飲） | 新（抽卡） | 出現位置 |
|---|---|---|
| 甜度／冰塊／珍珠 | 稀有度／數值／立繪 | 兩頁的 `IN_NAMES`、輸入滑桿標籤 |
| 評審 A／評審 B | 鑑定師 A／鑑定師 B | 兩頁的 `HID_NAMES` |
| 好喝程度 | 歐氣值 | `neural_network.html` 輸出節點 |
| 最後分數 | （不變，本來就是中性用詞） | `backpropagation.html` 輸出節點 |
| 老闆／主管 | 玩家／版主 | `backpropagation.html` 開場究責鏈比喻 |

### 訓練動畫節奏修正（連帶處理，同一次回饋提到）
`neural_network.html` 的自動訓練 (`train()`) 原本每個 tick 跑 25 個 epoch、間隔 60ms、上限 60 tick，收斂太快幾乎一閃而過。改成**每個 tick 跑 8 個 epoch、間隔 100ms、上限 150 tick**，讓誤差曲線與線條粗細變化的過程能被眼睛追蹤，同時保留「按下去看它自己變」的即時感（實測約 1.5–2 秒收斂到誤差 <2）。`backpropagation.html` 是逐輪手動／連跑 30 輪的機制，本來就不是自動連續訓練，不受這次節奏修正影響。

### 核心機制：權重指紋（weight fingerprint）
把模型全部 11 個權重與偏誤的絕對值加總成一個單一數字，當作「模型有沒有真的變」的視覺化證據：
- **推論模式**：不管怎麼換卡、送幾次推論、把小抄加到 +30，這個數字理論上動都不動
- **訓練模式**：按下「開始訓練」，沿用中級頁已定案的訓練節奏（每 tick 跑 8 epoch、間隔 100ms、上限 150 tick），指紋幾乎每一刻都在跳，並有短暫變色閃爍提示「它正在動」

頁面另有一個四階段管線圖（收集資料→訓練→凍結→推論），依模式即時切換高亮，訓練階段用磚紅色（`.back`）呼應反向傳播頁的配色語言。

### 小抄（context）互動
文字輸入＋加減分滑桿＋「套用小抄」切換鈕。套用後會顯示一條算式鏈：「模型真正算出來的 + 小抄加的分數 = 你看到的分數」，並明確標註權重指紋數值不變 —— 把「上下文視窗」抽象概念變成一個可以親手拆開看的機制。

### 三個挑戰卡
1. 在推論模式下想辦法讓指紋變（驗證凍結）
2. 切訓練模式盯著指紋跳動，訓練完切回推論驗證分數真的變了
3. 回想自己用 AI 的經驗，對照小抄實驗解釋「為什麼新對話它不記得你」

收尾三段呼應開場比喻、把 11 個權重的規模感接到真實模型的量級，最後留一個開放問題（「權重都不動，那 AI 講錯話是哪裡出錯？」）導向初級 3（AI 為什麼會錯）。頁尾「上一頁」連結也同步修正為 `rule_to_learning.html` 的真連結。

## 十四、why_ai_fails.html（初級 3/3）設計決定與完成（10/7）

初級最後一頁，拆「AI 錯是因為它還不夠聰明」這個誤解，要產生的理解是「資料裡沒有的東西它學不到，資料裡有的偏見它會忠實地學起來」。

### 設計決定

| 決定 | 選擇 | 理由 |
|---|---|---|
| 核心機制 | 沿用中級抽卡網路（同一套 3→2→1 架構），但換成「學生選訓練資料」而非「學生調權重／調輸入」 | 這頁的重點是資料本身造成的差異，不是模型結構；沿用架構讓讀過中級頁的人直接上手 |
| 資料設計 | 兩份各 5 張卡的訓練集（偏誤／平衡）＋ 1 份 5 張卡的測試集，正確答案全部來自同一條隱藏公式 `0.20×稀有度 + 0.15×數值 + 0.65×立繪` | 偏誤資料集的立繪固定為「華麗」，模型從未見過立繪變化，但測試題故意涵蓋低立繪卡 —— 讓「錯誤可預測」變成可以實際跑出來的數字，不是用講的 |
| 幻覺段落 | 固定對比範例為主，但加了一個小型「問一個沒見過的組合」查詢區（3 個滑桿 + 即時分數），重用同一個已訓練模型，不建立新的資料/訓練機制 | 使用者原本選的是「固定對比範例」，但純文字會讓前一段提到的「滑桿」失去著落點；用極輕量的重用元件補上，仍避免做成第二套完整的互動實驗室 |

### 核心流程
1. 學生用「偏誤資料／平衡資料」切換鈕選一份訓練集（切換時權重會重新隨機洗牌，確保每次比較都是公平的新起點）
2. 按「開始訓練」，沿用中級頁的訓練節奏（每 tick 跑 8 epoch、間隔 100ms、上限 150 tick）
3. 下方測試題表格即時顯示 5 張測試卡的真實分數、模型猜測、差距，訓練時每個 tick 都重算
4. 訓練紀錄會把每次結果（用哪份資料、測試誤差、錯最大的那張卡）加進一個可累積的清單，讓學生可以切資料重練、把兩次結果擺在一起比較，不需要同時維護兩個模型

### 實測結果（Playwright 跑出來的真實數字，不是預期值）
- 平衡資料訓練：測試誤差落在 5～12 分
- 偏誤資料訓練：測試誤差落在 48～56 分，且錯最大的幾張穩定落在低立繪的卡（最大落差曾到 74 分）
- 兩次訓練都會收斂（訓練集本身的誤差都能壓到 2 分以下），證明不是「模型沒訓練好」，純粹是資料造成的泛化失敗（呼應 `overfit`／`general` 兩個已先備好的術語）

### 幻覺段落
- 輕量查詢區：重用剛剛訓練好的模型權重，3 個滑桿可以設一組訓練/測試資料裡都沒出現過的組合，即時顯示模型依然會給一個明確分數，沒有「不知道」的選項
- 真正的對比範例：虛構一本不存在的書《新手村標準教科書》，示範語言模型如何「編出一個聽起來很順的頁碼和引文」——把玩具模型的現象接到真實語言模型的幻覺

### 收尾與導覽
收尾三段把 5 張卡的資料偏差接到真實模型幾十億筆資料的規模，點出幻覺是模型「永遠要給答案」的天性而非單次失誤，最後導向「該問資料不該問聰不聰明」，並把問題帶回中級頁（下一頁：神經網路）形成完整的閱讀迴圈。頁尾「上一頁／下一頁」都已修正為真連結（`training_vs_inference.html`／`neural_network.html`），`index.html` 的初級 3 卡片也拿掉「規劃中」並連到這一頁 —— 初級三頁全部完成。

### 驗證與同步
Playwright（mobile viewport）驗證：無 JS 錯誤、無版面溢出；平衡／偏誤資料訓練後測試誤差數字如上；訓練紀錄正確累積兩筆（用 `waitForFunction` 等按鈕文字變回「再訓練一次」才讀取，避免誤判成只有一筆）；滑桿查詢區即時更新分數。三個檔案（`index.html`、`docs/roadmap.md`、`pages/why_ai_fails.html`）已同步回裝置並逐一驗證位元數與關鍵字。

## 十七、把抽卡類比換成垂圾信過濾（10/12）

使用者回饋：中級三頁＋初級 2、3（神經網路、梯度下降、反向傳播、訓練與推論、AI 為什麼會錯，共用同一個「抽卡鑑定」3→2→1 網路）這個類比有兩個問題——

1. **類比不夠清楚**：稀有度／數值／立繪 → 卡片價值，跟真實 AI 應用（分類、過濾、生成）的距離有點遠，不容易直接看出「這就是 AI 在做的事」。
2. **用太多次會乏味**：同一個抽卡情境在 4 個頁面重複出現，看到第 3、4 次容易疲乏。

討論後決定：**保留同一個情境貫穿這 4 頁**（維持教學上的 scaffolding 優點——讀者不用每頁重新理解新情境），**只把類比換成更貼近真實 AI 應用的主題**：垂圾訊息過濾（這封信是不是垂圾信），因為這是最常見、一看就懂的「這就是 AI 在做的事」範例。

### 對應關係

因為底層的訓練資料（11 個權重、5 筆資料的數值）完全不變，只換了「這些數字代表什麼」，所以前向傳遞／梯度下降／反向傳播的程式邏輯都不用重寫，純粹是文字與標籤置換：

| 舊（抽卡類比） | 新（垂圾信過濾） |
|---|---|
| 稀有度 / 數值 / 立繪（3 個輸入） | 連結數 / 緊急語氣 / 寄件人（3 個輸入） |
| 鑑定師 A / B（隱藏層） | 審核員 A / B（隱藏層） |
| 歐氣值（輸出） | 垂圾分數（輸出） |
| 版主（反向傳播頁的究責對象） | 站長 |
| 「送去鑑定」 | 「送去過濾」 |
| 阿哲抽過的卡、他的品味 | 阿哲信箱裡的信、他的分類習慣（人物「阿哲」保留，只是他現在標的是信不是卡） |

AI 為什麼會錯（why_ai_fails.html）的偏誤資料設計也因此變得更貼切：偏誤訓練集原本固定「立繪=華麗」，現在是固定「寄件人=完全不認識」——也就是模型只看過「寄件人是陌生人」的垂圾信範例，對「寄件人其實算熟」的信會判斷失準。這直接對應真實世界垃圾信過濾器的已知弱點（例如對熟人帳號被冒用的釣魚信判斷失準），比原本的「卡片立繪」類比更貼近真實 AI 應用的限制。

### 執行方式
因為只是置換標籤文字，不動程式邏輯，用 Python 腳本逐一比對每段要換的文字（含 HTML 標籤、JS 字串、函式名稱 `rarityLbl`/`powerLbl`/`artLbl`/`cardText` 改名為 `linkLbl`/`urgencyLbl`/`senderLbl`/`mailText`），每一組都先檢查目前檔案裡出現的次數剛好符合預期才真的替換，避免誤改到不該改的地方或漏改。4 個檔案（`neural_network.html`、`backpropagation.html`、`training_vs_inference.html`、`why_ai_fails.html`）都跑過這套流程，再逐一用全文搜尋確認沒有殘留的舊用語（稀有度／立繪／鑑定師／抽卡／版主／杯子／卡片／張卡等）。
